# Veriforge MVP Scope

## MVP goal

Build the first usable Veriforge experience as an evidence-first personal proof system.

The MVP must not become a generic portfolio. It must prove how I think, build, test, debug, decide, fail, fix, and improve.

## MVP modules

### 1. Mission Control

Purpose: explain Veriforge in ten seconds and route visitors into proof.

Must include:

- Veriforge name
- tagline: Where my work becomes proof
- one-paragraph positioning
- Now / Next / Later project grouping
- primary actions into Case Files, Proof Claims, Proof Wall, and Interview Mode

### 2. My Narrative

Purpose: explain the professional story.

Must include:

- QA foundation
- debugging mindset
- automation systems
- AI safety/control systems
- approval infrastructure
- product-building direction

### 3. Proof Claims

Purpose: replace generic skill lists with evidence-backed claims.

Initial claims:

- I design control systems for risky automation.
- I debug complex automation systems by separating symptoms from root causes.
- I turn vague ideas into structured, testable, buildable systems.
- I use QA thinking to design safer product workflows.
- I create human-in-the-loop systems where automation needs control.

Each claim must link to at least one case file or proof item.

### 4. Case Files

MVP case files:

- VF-001: Aixion Control Tower
- VF-002: MCP Shield
- VF-003: Tradebot

Next-line case files can appear as lighter entries:

- VF-004: RTI App
- VF-005: TabLock Guard / TabGuard WorkLock
- VF-006: Job Application Agent

Each flagship case file must include:

- problem
- why it matters
- my role
- system design
- key decisions
- failure log
- testing strategy
- proof
- proof gaps
- before / after
- demo readiness
- what I would improve next

### 5. Proof Wall

Purpose: show cross-project evidence.

MVP evidence types:

- PR
- test
- architecture
- product bible
- failure fix
- decision
- demo target
- CI/CD proof

Each proof item must include:

- title
- project
- type
- claim supported
- maturity
- status

### 6. Failure Ledger

Purpose: show maturity through honest failure analysis.

Each entry includes:

- failure
- bad assumption
- root cause
- fix
- test added or needed
- what it proves

### 7. Decision Ledger

Purpose: show engineering and product judgment.

Each entry includes:

- decision
- context
- chosen path
- rejected path
- reason
- tradeoff

### 8. Build Log

Purpose: keep Veriforge alive as future projects grow.

Each entry includes:

- date
- project
- what changed
- what broke
- what I learned
- proof link

### 9. Operating Style

Purpose: explain how I work.

Initial principles:

- I turn vague ideas into scoped systems.
- I prefer proof over claims.
- I treat failures as debugging material.
- I care about controls, tests, and real execution.
- I do not consider a project serious until it has proof.

### 10. Interview Mode

Purpose: guide different audiences to relevant proof.

MVP modes:

- Recruiter Mode
- Technical Interviewer Mode
- QA Lead Mode
- AI Safety Mode
- Founder Mode

Each mode should point to case files, proof items, and evidence packs.

## Out of scope for MVP

Do not build these first:

- full AI chatbot
- GitHub API sync
- PDF generator
- login/auth
- admin dashboard
- database
- heavy animation system
- too many case files

Reason: AI over weak evidence is useless. Build strong content and structure first.

## V1 after MVP

After MVP:

- Ask Veriforge chatbot
- search across case files
- role-based evidence packs
- PDF export
- GitHub proof links
- demo video embeds
- case file maturity badges

## V2 later

Later:

- GitHub API proof sync
- automatic PR/test evidence ingestion
- evidence graph visualization
- admin editor
- public/private evidence controls
- AI-generated role-fit report

## MVP acceptance criteria

The MVP is acceptable only if:

- the homepage explains the concept within ten seconds
- flagship case files are first-person and evidence-backed
- each claim links to proof
- project maturity is visible
- failures and decisions are included
- no generic passionate-learner language appears
- the site does not look like a normal resume template
